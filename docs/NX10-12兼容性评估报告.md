# NX 10 / NX 12 向下兼容性评估报告

> 对象: `nx_extrude_runner.py`（DXF 解析 → NX 建模，现基于 NX 2312）
> 本报告已由"评估"升级为"实机定案 + 修复落地"：根因全部经 NX10/NX12 真机探针确认，代码侧兼容改动已并入主脚本。
> 配套探针 `probe_nx_compat.py`（现 **v2.2**）；实机结果存于 `NX10logs/`、`NX12logs/`。
> 状态图例：✅ 已确认并修复 ｜ 🔵 已确认（无需改代码）｜ ⏳ 待复测（探针 v2.2 / 端到端）。
> 行号指当前主脚本。

## 0. 一页结论

- **真正的兼容断点只有 2 个 NXOpen 绑定层问题**（不是早期报告误判的"2 处 Python 语法项"）：
  1. ✅ `Section.AddToSection` 的 seed/两个 connector 在 NX10/12 **不接受裸 `None`**，要类型化空对象 `NXOpen.NXObject.Null`。
  2. ✅ `ScRuleFactory.CreateRuleOptions` 在 NX10/12 **根本不存在**，旧版规则工厂只有无 `ruleOptions` 的单参重载。
- **Python 层**：仅 NX10（3.3.2）缺 `importlib.util.spec_from_file_location`（✅ 已三级梯兜底）；`ast.AsyncFunctionDef` 只影响 `--selftest`（期刊执行不触发，⏳ 未动）。
- **其余全部实测通过**：dlx 加载、布尔、删参、测量、着色、图层、装配加件、矩阵回退——均 ✅，无需改动。
- **stdparts 标准件库**：探针 API017 在 NX10/NX12 均成功加载真实 .prt（6 参 AddComponent）→ **未见版本不兼容**（推翻早期判断）。⏳ 端到端装配仍建议实测一次。
- **重大发现（决定打法）**：NX10/12 的 `NXOpen.pyd` 是 **Siemens 自研 CPython C 扩展绑定，非 pythonnet**——无 `System` 模块、对象无 `GetType()`/反射、无 `.array()`。故"造 .NET 数组 + 反射签名"的路线在这两版物理上不可行；改走"抓绑定自带 `__doc__` + 参数二分"才定位到根因。

## 1. 依赖全景与实机事实

### 1.1 分层风险（实机后）

| 层 | 内容 | 早期评估 | 实机结论 |
|---|---|---|---|
| Python 解释器 | 期刊自带 Python | 低 | ✅ NX10 需 importlib 兜底（已修）；NX12 无断点 |
| NXOpen 建模主链 | 拉伸/布尔/提升/删参/倒圆/删面/测量 | 低~中 | ✅ 断点仅 AddToSection-null 与 CreateRuleOptions（均已修） |
| BlockStyler 对话框 | 3 个程序生成 .dlx + 回调 | **高（未验证）** | 🔵 两版均可加载（含 2312 版本戳），**零改动** |
| UF API | 仅 AskFaceData 等 | 极低 | 🔵 可用 |
| 自研 DXF/几何 | 纯 Python | 零 | 🔵 与 NX 无关 |
| 配置/记忆 | nx_std_config.py + params.json | 零 | 🔵 纯数据 |

### 1.2 绑定层技术栈（关键）

| NX | 期刊 Python | NXOpen 绑定 | 反射/`System`/`.NET 数组` |
|---|---|---|---|
| NX10 | 3.3.2 | 自研 CPython C 扩展 | ❌ 无（`No module named 'System'`、无 `GetType`） |
| NX12 | 3.6.1 | 自研 CPython C 扩展 | ❌ 无（同上） |
| NX2312 | 3.10+ | 同系更新版 | 版本对 list→数组、None→空指针做了更宽容的自动编组 |

> 影响：跨版本差异表现为"同一 Python 代码，新绑定能编组、旧绑定报 `没有过载与这些参数匹配`"，且**无法用 pythonnet 反射/建 .NET 数组绕开**。定位手段只能是：读方法 `__doc__`（含真实重载与参数类型说明）+ 对可疑参数逐一试形态。

## 2. 已确认并修复的兼容障碍（代码侧）

### 2.1 ✅ `AddToSection` 类型化空对象（根因 #1）

- **现象**：`section.AddToSection([rule], None, None, None, hp, Mode.Create, False)` 在 NX10/12 抛 `TypeError: 没有过载与这些参数匹配`；NX12 回显实参类型 `(list, NoneType, NoneType, NoneType, Point3d, SectionModeMemberType, bool)`。
- **定位**：旁证 `ReplaceRules(收 list)`、`CreateLine(收 Point3d)` 在旧版均成功 → 洗清 `rules` 用 list、`helpPoint` 用 Point3d；`__doc__`（探针 API021）确认签名与 2312 一致 → 卡点只剩 AddToSection 独有的 `seed/两 connector` 的裸 `None`。二分实测：换成 `NXOpen.NXObject.Null` 即通（探针 API006 由 ERROR→AVAILABLE）。
- **修复**：`_add_to_section_compat(section, rules, help_pt)`（主脚本 L2176，`extrude_curves` L2243 调用）——**先按 2312 原式（`None`）调用，保证现网逐字节零回归；仅当抛异常才用 `NXObject.Null` 重试**。

### 2.2 ✅ `CreateRuleOptions` 缺失（根因 #2）

- **现象**：EdgeBlend / DeleteFace 里 `part.ScRuleFactory.CreateRuleOptions()` 在 NX10/12 抛 `AttributeError`（该属性不存在）。`__doc__`（API023/025）显示旧版 `CreateRuleFaceDumb(faces)`、`CreateRuleOuterEdgesOfFaces(faces)` 只有单参重载。
- **修复**：`_sc_rule_options(work_part)`（L2200）取不到即返回 `None`；EdgeBlend（L2945）、DeleteFace（L3153）据 `opts is None` 走无-opts 单参重载。2312 仍传 opts（零回归）。

### 2.3 ✅ EdgeBlend 核心属性逐条守卫

- 原 `Tolerance/AllInstancesOption/RemoveSelfIntersection/PatchComplexGeometryAreas/LimitFailingAreas` 为裸赋值，旧版缺任一项即整条倒圆崩。
- **修复**：L2963 改逐属性 `try`，缺哪个跳哪个；后 9 项行为/枚举属性本就在一个 try 块内。

### 2.4 ✅ NX10 配置加载三级梯

- `_import_module_from_path(name, path)`（L365）：`importlib.util`(3.4+) → `imp.load_source`(3.3/NX10) → `compile+exec`(3.x 全覆盖)。仅"能力缺失"下梯，真实加载错照常上抛记录。

## 5. 探针 `probe_nx_compat.py`（v2.2）说明

- **分组**：PY（解释器能力）/ VER（版本探测）/ API（建模主链分步 S1~S7）/ **MAR**（各数组参数 list-vs-数组体检）/ UI（BlockStyler）。
- **S3 定位法**：因无 pythonnet 反射，改**两遍二分**——Pass1 固定 `carrier=list, hp=Point3d`，只在 `类型化null × seed × mode枚举/整型 × 元数6/7` 上试；Pass2 才放宽载体(tuple/single)与 helpPoint(tuple3/list3/None)。首个成功写入 `_GOOD`，`API020` 直接吐"runner 照此写"配方。
- **签名自省**：`API021~025` dump 绑定自带 `__doc__`（自研绑定无反射时，这是看真实参数类型的唯一权威通道；已 dump AddToSection / CreateRuleBaseCurveDumb / CreateRuleFaceDumb / CreateUniteFeature / CreateRuleOuterEdgesOfFaces）。
- **运行**：
  ```
  方式1(推荐, UI 组有效): NX 内 工具→日记→播放 选 probe_nx_compat.py（与 stdparts 同目录）
  方式2(批量): <NX>\NXBIN\run_journal.exe probe_nx_compat.py
  方式3(自检): 任意外部 Python 直跑 —— 仅 PY 组照跑, 其余 SKIP
  输出: logs\nx_compat_probe.json + .csv（UTF-8 BOM）
  ```
- **判读**：`AVAILABLE/MISSING/ERROR/SKIP/INFO`；API/UI 项"核心调用成功"即 AVAILABLE，完整 Commit 结果在 detail。
