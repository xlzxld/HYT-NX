## 0. 一页结论

- **代码侧兼容断点共 4 个 NXOpen 绑定层问题**（均已在 runner 修复，2312 零回归）：
  1. ✅ `Section.AddToSection` 的 seed/两个 connector 在 NX10/12 **不接受裸 `None`**，要类型化空对象 `NXOpen.NXObject.Null`。（`_add_to_section_compat`）
  2. ✅ `ScRuleFactory.CreateRuleOptions` 在 NX10/12 **根本不存在**，旧版规则工厂只有无 `ruleOptions` 的单参重载。（`_sc_rule_options`）
  3. ✅ `NXOpen.Expression` 在 NX10/12 **无 `SetFormula` 方法**，只有 `.RightHandSide=str`（旧版拉伸的 offset/draft 因此崩，JRT 全废）。（`_set_expr`）
  4. ✅ `BlockStyler.BlockDialog` 在 NX10/12 **无 `Launch()`**（2312 才有）→ 旧版交互弹窗报 `'BlockDialog' object has no attribute 'Launch'`。（`_dlg_show`：按存在性选 Launch→Show→ReplayDialog）
- **Python 层**：仅 NX10（3.3.2）缺 `importlib.util.spec_from_file_location`（✅ 已三级梯兜底）；`ast.AsyncFunctionDef` 只影响 `--selftest`（期刊执行不触发，⏳ 未动）。
- **建模主链端到端已通**：v2.3 探针在 NX10/NX12 实测 **API006(拉伸全链) / API010(EdgeBlend 圆角全属性+AddChainset+Commit) / API011(DeleteFace) 均 AVAILABLE**——三处代码修复坐实。
- **stdparts 标准件库（纯交付侧约定，代码不切换目录）**：⚠ 早期探针 API017 曾"可加载"，但 **v1.36「标准件归零」用 2312 重存了 stdparts**，致旧版 `AddComponent` 现报"不是部件文件(NX10)/更新版本(NX12)"——`.prt` 只向下不向上兼容。**做法（不改 stdparts 目录名）**：旧版机上用 `tools\NX向下兼容工具\` 的链路（`export_xt.py` 把母版导 x_t → `verify_import.py` 校验回读零丢失 → 拷整个文件夹到旧版机双击 `一键导入.bat` / `import_xt_to_prt.py` 还原成**本机版本 .prt**），产出的旧版 .prt **直接放进 `stdparts\`（覆盖同名）**；runner 的 `stdparts_dir()` 就按 `STDPARTS_DIRNAME=stdparts` 固定读，无按版本分支。NX2312 端到端已实测：14 个 x_t 导出、回读校验零丢失、导入 14/14 OK。⏳ 待低版本机导入产出 .prt 放入 `stdparts\` 后复验 AddComponent。
- **重大发现（决定打法）**：NX10/12 的 `NXOpen.pyd` 是 **Siemens 自研 CPython C 扩展绑定，非 pythonnet**——无 `System` 模块、对象无 `GetType()`/反射、无 `.array()`。故"造 .NET 数组 + 反射签名"的路线在这两版物理上不可行；改走"抓绑定自带 `__doc__` + 参数二分 + 端到端 batch 实测"才逐一定位根因。

## 2. 已确认并修复的兼容障碍（代码侧）

### 2.1 ✅ `AddToSection` 类型化空对象（根因 #1）

- **现象**：`section.AddToSection([rule], None, None, None, hp, Mode.Create, False)` 在 NX10/12 抛 `TypeError: 没有过载与这些参数匹配`；NX12 回显实参类型 `(list, NoneType, NoneType, NoneType, Point3d, SectionModeMemberType, bool)`。
- **定位**：旁证 `ReplaceRules(收 list)`、`CreateLine(收 Point3d)` 在旧版均成功 → 洗清 `rules` 用 list、`helpPoint` 用 Point3d；`__doc__`（探针 API021）确认签名与 2312 一致 → 卡点只剩 AddToSection 独有的 `seed/两 connector` 的裸 `None`。二分实测：换成 `NXOpen.NXObject.Null` 即通（探针 API006 由 ERROR→AVAILABLE）。
- **修复**：`_add_to_section_compat(section, rules, help_pt)`（主脚本 L2176，`extrude_curves` L2243 调用）——**先按 2312 原式（`None`）调用，保证现网逐字节零回归；仅当抛异常才用 `NXObject.Null` 重试**。

### 2.2 ✅ `CreateRuleOptions` 缺失（根因 #2）

- **现象**：EdgeBlend / DeleteFace 里 `part.ScRuleFactory.CreateRuleOptions()` 在 NX10/12 抛 `AttributeError`（该属性不存在）。`__doc__`（API023/025）显示旧版 `CreateRuleFaceDumb(faces)`、`CreateRuleOuterEdgesOfFaces(faces)` 只有单参重载。
- **修复**：`_sc_rule_options(work_part)`（L2200）取不到即返回 `None`；EdgeBlend（L2945）、DeleteFace（L3153）据 `opts is None` 走无-opts 单参重载。2312 仍传 opts（零回归）。

### 2.3 ✅ EdgeBlend 核心属性逐条守卫

- 原 `Tolerance/AllInstancesOption/RemoveSelfIntersection/PatchComplexGeometryAreas/LimitFailingAreas` 为裸赋值，旧版缺任一项即整条倒圆崩。
- **修复**：L2963 改逐属性 `try`，缺哪个跳哪个；后 9 项行为/枚举属性本就在一个 try 块内。

### 2.4 ✅ NX10 配置加载三级梯

- `_import_module_from_path(name, path)`（L365）：`importlib.util`(3.4+) → `imp.load_source`(3.3/NX10) → `compile+exec`(3.x 全覆盖)。仅"能力缺失"下梯，真实加载错照常上抛记录。
