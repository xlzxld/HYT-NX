## 标准件 NX 版本降级导出（stdparts 目录）

**结论：NX10 原生 .prt 在本机不可能生成。**
- 本机只有 NX2312 完整安装（`C:\Program Files\Siemens\NX2312`）；`NX2306` 目录只剩 NXNASTRAN，不是可用安装；无 NX10 / NX8。
- NX 没有任何"另存为旧版本 .prt"的能力：`ug_convert_part.exe` 只做英寸/毫米单位换算；`UF_PART_export_with_options` 无版本参数；`UGII` 下无降级工具。
- 因此走 Parasolid 降级导出。

**做法**：NX2312 批处理 journal（Python 3）调 `NXOpen.ParasolidExporter`，`ExportFrom=ExistingPart` + `InputFile=<prt>`（无需打开部件），`ParasolidVersion=Ps240Nx80`（PS 24.0 = NX8）。
- PS 24.0 向后覆盖：NX8 及以后（含 NX10）全部可读，一套文件通吃，无需再出 NX10 一套。
- 可用版本枚举见 `UGOPEN\NXOpen\ParasolidExporter.hxx`（Ps240Nx80=240 … Ps351Nx2306=351）。
- 14 个部件全部导出成功并回读验证通过（实体数正常，无失败）。

**产出**：`NX8兼容_x_t/` 14 个 .x_t；journal 与日志在 `_nx_export/`（`export_ps.py`、`verify_import.py`、`report.txt`、`verify.txt`）。
注意：x_t 是无参数历史的哑实体，对方在 NX8/NX10 导入后另存即可。

## 追加：x_t → NX10 .prt 的一键导入脚本

用户嫌手动在 NX10 里一个个导入保存太麻烦（十几个），要求代劳。**本机做不了最终产物
（无 NX10），但可以完全自动化操作本身**——写了 `NX8兼容_x_t\import_to_nx10.py` +
`一键导入.bat` + `使用说明.txt`，用户在 NX10 机器上双击即自动导入全部 14 个并保存为 .prt
（输出到上级目录 `NX10_prt`）。已在 NX2312 上跑通验证（2/2 通过，实体数与源件吻合）。

脚本要点（跨 NX8~NX2312 通用，py2/py3 兼容写法）：
- 源目录 = 脚本自身所在目录（`os.path.dirname(__file__)`），或命令行传参；输出 = 上级目录 `NX10_prt`。
- 用 `uf.Part.CloseAll()` → `uf.Part.New(prt, 1)` → `uf.Ps.ImportData(xt)` → `uf.Part.Save()`，
  全走 UF 层，避开 NXOpen 枚举在各版本间的差异。
- 单位已确认：**14 个源件全部为毫米**（`part.PartUnits == 1`），脚本按 mm 建部件。
- 实体数对照（源件与 x_t 回读**逐个吻合，零丢失**，见 units.txt）：
  主进胶与中心定位垫片-30/-35 = 7/7；压线板 2；垫片 2；大水口-18/25/35 = 2/2/2；
  接线盒-16针 1、-24针 2、-48针 3；点胶口-18 2、-25 2；螺丝-45 2、-50 2。

**环境/接口坑（补充）**
- `uf.Part.Open(path)` 少传参数会 **内存访问违规** 并让整个 session 崩；用 `s.Parts.Open(p)`，
  且它**返回 tuple** `(part, loadStatus)`，要取 `[0]`。
- `NXOpen.BasePart.CloseWholeTree` 枚举**没有** `True` 成员（getattr 也取不到），别用它；
  改用 `uf.Part.CloseAll()`。
- `UF_MODL_ask_bounding_box` / `UF_OBJ_ask_bounding_box` 在 NX2312 头文件里**已不存在**，
  包围盒取不到，日志改用实体数 + 文件体积做校验。
- NX2312 journal 用 **Python 3**（不是 IronPython 2），`except X as e` 语法。
- Python 枚举名要去掉类型前缀：`Current` 而非 `ParasolidVersionOptionCurrent`。
- `NXOpen.BasePart.CloseWholeTree.True` 是语法错误（`True` 是关键字），要用 `getattr(...,"True")`。
- `run_journal.exe` 的 stdout 经管道常被吞（exit 127），可靠输出在 `%TEMP%\*.syslog`，或让 journal 自己写报告文件。
- `Parts.FileNew` 用模板路径报 "template doesn't exist"，改用 `uf.Part.New(path, 1)`（1=毫米）可行。

## 追加 2：NX10 导入全失败 —— 中文路径/中文名编码坑（v2 修复）

用户在 NX10 上跑 v1 脚本，14 个**全部**失败：
`期望的是语言环境数据，但检测到 UTF8 数据。`
根因是**两处** UTF-8，我 v1 只想到路径那处：
1. **中文路径传给 NX**：NX10 默认跑在本地代码页（GBK）模式，NX2312 默认 UTF-8 模式，
   所以这坑**只在 NX10 上出现**，我在 NX2312 上测通属于假阳性。
2. **x_t 文件内部嵌了 UTF-8 中文零件名**：NX 的 Parasolid 导出器会把源件名写进文件头。
   实测 14 个 x_t 每个都含 6~30 个非 ASCII 字节（正是零件名的 UTF-8）。
   → 只改路径没用，NX 读文件时照样撞。

**修复（两处都掐断，缺一不可）**
- 导入侧：`import_to_nx10.py` 改成 **ASCII 中转**。中文活儿全交给 Python（listdir /
  copyfile / rename 都 Unicode 安全），NX 只接触 `i000.x_t`、`i000.prt` 这类纯 ASCII
  暂存路径；存完 Python 再 `os.rename` 改回中文名。
- 导出侧：`export_ps_v2.py` 把源 prt 先复制成 `p000.prt` 再导出，让嵌入名也变成 ASCII，
  然后改回中文文件名。结果：14 个 x_t 内部非 ASCII 字节数 **= 0**。
- 回读验证 14/14 实体数与源件吻合。顺带确认导入后 **body.Name 为空**（不是残留英文名），
  ASCII 中转无副作用。

**教训（重要方法论）**
- 在 NX2312 上测通 ≠ 老版本能跑。涉及 NX 的编码行为，必须在**目标版本**上验，
  或者干脆用「只喂 ASCII」这种版本无关的方案。
- 排查编码问题时要分清**路径编码**和**文件内容编码**两个独立来源，别只修一处。

**数据小问题（已证伪，勿再提）**：曾以为 `点胶口-18..prt` 多一个点。字节级确认（Python
`len()==10`、`utf-8 hex = ...2d31382e707274`）实际是 `点胶口-18.prt`，**单个点**。之前 `ls`
输出显示成两个点是终端渲染假象——凡涉及中文文件名，必须字节级核对，不能信 ls 的文本输出。
