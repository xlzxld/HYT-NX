标准件 x_t 导入 NX10 —— 使用说明（v2）
=====================================

【重要：如果你之前已经拷过一遍 x_t，请重新拷】
v1 的 x_t 在 NX10 上报「期望的是语言环境数据，但检测到 UTF8 数据」，14 个全失败。
原因是两处 UTF-8 撞上了 NX10 的本地代码页模式（GBK）：
  1) 中文路径传给 NX；
  2) NX 导出时把中文零件名写进了 x_t 文件内部。
v2 两处都解决了（见下）。请用 v2 的 x_t + v2 的脚本，整套重新拷一次。


【一句话】
把整个文件夹拷到装了 NX10 的电脑上，双击「一键导入.bat」，14 个 .prt 会自动生成在
上一级目录的 NX10_prt 文件夹里。


【v2 做了什么】
1. import_to_nx10.py：NX 只接触纯 ASCII 的临时路径。
   中文的活儿全交给 Python（列目录、复制、重命名都是 Unicode 安全的）：
   先把 x_t 复制成 i000.x_t 这种英文名 → NX 导入并保存为 i000.prt →
   Python 再把它改名成中文的 垫片.prt。NX 全程没见过中文路径。
2. x_t 重新导出过一遍：源件先复制成 p000.prt 这种英文名再导出，
   这样文件内部嵌入的零件名也变成纯英文，不再是 UTF-8 中文。
   已逐个确认：14 个 x_t 内部非 ASCII 字节数 = 0。


【三种运行方式，任选其一】
1) 双击 一键导入.bat        （推荐，自动找 NX 安装位置）
2) NX 界面里：文件 → 执行 → NX Open → 选择 import_to_nx10.py
3) 命令行：
   "C:\Program Files\Siemens\NX 10.0\NXBIN\run_journal.exe" "import_to_nx10.py"

bat 若报 "not found"，说明没自动找到 NX 路径，改用方式 2，效果一样。


【输入输出】
- 源目录：本脚本所在文件夹（放 x_t 的这个）
- 输出目录：上一级目录下的 NX10_prt
- 日志：本文件夹下的 import_log.txt（跑完看有没有 FAIL 行）


【万一还报编码错误】
现在 NX 只会看到纯 ASCII 路径，理论上不会再撞编码。真要还有，最快的办法：
把这一整个文件夹挪到一个**纯英文路径**下再跑，例如
  C:\NX\xt\  →  输出会落在 C:\NX\NX10_prt\
（注意：NX10_prt 这个输出目录的父路径也必须是英文的。）

【已经确认过的事】
- 源件全部毫米单位，脚本按毫米新建部件，不会出现尺寸差 25.4 倍的问题。
- x_t 是 Parasolid 24.0（NX8 schema）。NX8 / NX10 / NX12 及更新版本都能直接读。
- v2 的 14 个 x_t 已回读验证，实体数与源件逐个吻合，零丢失。
- 导入后实体名为空（不是残留的英文名），没有副作用。


【必须知道的局限】
- 导入得到的是「哑实体」：只有几何体，没有特征树、草图、表达式。想改尺寸只能
  用同步建模推面，改不了原始参数。要保留参数历史，唯一办法是在 NX10 里重新建模，
  或者找一台装了 NX10 的机器从原始 prt 另存。
- NX 无法把新版本 prt 降级另存成旧版本，所以走的 Parasolid 这条路，代价就是丢参数。


【单位如果要改】
打开 import_to_nx10.py，把开头的 UNITS = 1 改成 2 就是英寸。（1 = 毫米，2 = 英寸）
